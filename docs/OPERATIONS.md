# Эксплуатация IPCHEK

IPCHEK работает только на Mac владельца. Сервера, базы в облаке и секретов нет.

## Сборка и запуск для разработки

```bash
make run
```

Запускается **IPCHEK Dev** (`com.lavmoviesstudio.ipchek.dev`) — отдельное приложение со своими настройками.

## Установка рабочей версии

Появится на этапе 7 (команда установки в «Программы» и автозапуск). До этого рабочая версия собирается командой `make build-release` в папку `build/DerivedData/Build/Products/Release/`, но не устанавливается.

## Обновление

1. `git pull`
2. `make verify` — должно закончиться строкой «✅ make verify: все проверки пройдены».
3. Установка (с этапа 7).

## Откат

1. Посмотреть версии: `git tag`.
2. Перейти на нужную: `git checkout <тег>`, затем собрать и установить её.
3. Вернуться к свежей версии: `git checkout main`.

## Журналы

Приложение пишет журнал в системный журнал macOS (подсистема `com.lavmoviesstudio.ipchek`, для отладочной версии — `com.lavmoviesstudio.ipchek.dev`).

- **Программа «Консоль»:** нажать «Начать», в поиске ввести `com.lavmoviesstudio.ipchek`.
- **Терминал**, в реальном времени (полный путь `/usr/bin/log` обязателен: в zsh есть встроенная команда `log` с тем же именем):

```bash
/usr/bin/log stream --predicate 'subsystem BEGINSWITH "com.lavmoviesstudio.ipchek"' --level info
```

Подробные строки о каждой проверке связи пишутся уровнем `debug`: macOS их не хранит, они видны только в реальном времени с ключом `--level debug`:

```bash
/usr/bin/log stream --predicate 'subsystem BEGINSWITH "com.lavmoviesstudio.ipchek"' --level debug
```

В журнал не пишутся адрес сервера в Нидерландах и прочие чувствительные данные.

## Где лежат данные

Приложение работает в «песочнице», поэтому все его данные лежат в одной папке:
- рабочая версия — `~/Library/Containers/com.lavmoviesstudio.ipchek/`;
- отладочная — `~/Library/Containers/com.lavmoviesstudio.ipchek.dev/`.

Сейчас там только настройки. С этапа 6 появится история.

Настройки меняются в окне «Настройки» (кнопка в панели). Кнопка «Вернуть значения по умолчанию» возвращает значения из паспорта. Если файл настроек повреждён, приложение при запуске возьмёт значения по умолчанию и запишет об этом в журнал.

**Резервная копия** — Time Machine, если она включена. Отдельных бэкапов нет: данные локальные и восстанавливаемые.

## Полное удаление

1. Меню значка → «Выйти из IPCHEK».
2. Удалить приложение из «Программ» (с этапа 7).
3. Удалить папку с данными (см. выше).
4. Разрешение на уведомления убирается в Системных настройках → Уведомления.

## Секреты и их смена

Секретов нет. Адрес VPN-сервера в Нидерландах хранится только в настройках приложения на этом Mac — не в коде, не в репозитории и не в журнале. Если сервер сменился, впишите новый адрес в настройках («Настройки» → «Сервер в Нидерландах» → «Сохранить»).

## Если строка «Сервер NL» пишет «не отвечает», а VPN работает

Сервер проверяется TCP-соединением напрямую через Wi-Fi/кабель на порты 443 и 22. Если на сервере открыт другой порт (например, только ваш VPN-порт или SSH на нестандартном порту), выберите в настройках «Только мой порт» и впишите его. Ping не используется: «песочница» macOS не даёт приложению принять ответ на него.

## Значок приложения

Рисуется скриптом: `make icon` перезаписывает `App/Assets.xcassets/AppIcon.appiconset`. macOS кэширует значки — после смены значка может понадобиться перезапуск приложения.

## Если уведомления не приходят

1. Системные настройки → Уведомления → IPCHEK (или IPCHEK Dev): уведомления должны быть разрешены.
2. Проверьте, не включён ли режим «Не беспокоить» / фокусирование.
3. Если приложения нет в списке или в журнале есть «Запрос разрешения на уведомления не удался» — macOS не принимает локальную подпись. Тогда нужно подписать приложение бесплатным Apple ID (см. docs/DECISIONS.md, решение 4).

## Если кончился лимит автопроверок GitHub

Проверки на GitHub остановятся до начала следующего месяца, денег не спишут (карта не привязана). Локальная проверка `make verify` и проверка перед коммитом продолжают работать.
