# Журнал решений

Формат записи: что решили → почему → какие были альтернативы → источник.

## 2026-11-06 — фаза 2, каркас

### 1. Нативное приложение: Swift 6 + SwiftUI, значок через `MenuBarExtra`
- **Почему:** лёгкое, выглядит как часть macOS, всё нужное есть в Xcode, ноль сторонних библиотек.
- **Альтернативы:** Python + `rumps` — нужен Python, менее надёжные уведомления и автозапуск, нет пути к виджету.
- **Источник:** паспорт, раздел 8; сигнатуры `MenuBarExtra(_:systemImage:content:)` и `.menuBarExtraStyle(.menu)` сверены по SwiftUI.swiftinterface в macOS SDK 26.5 (Xcode 26.6).

### 2. Логика — в локальном пакете `Packages/IPCheckCore`, приложение — в `App/`
- **Почему:** логику можно тестировать командой `swift test` за секунды, без сборки и запуска приложения. Приложение остаётся тонкой оболочкой.
- **Альтернативы:** тесты внутри проекта Xcode — медленнее, тянут интерфейс.

### 3. Проект Xcode генерируется XcodeGen 2.45.4 из `project.yml`, `.xcodeproj` в git не хранится
- **Почему:** `project.yml` — 60 читаемых строк вместо огромного служебного файла Xcode, в котором трудно увидеть изменения и легко получить конфликт.
- **Альтернативы:** хранить `.xcodeproj` в git.
- **Источник:** XcodeGen 2.45.4, Docs/ProjectSpec.md (разделы Target, Local Package, Scheme).

### 4. Подпись — локальная (ad-hoc), без Apple ID
- **Почему:** бесплатно и без входа в аккаунт. Проверено: сборка подписывается и проходит `codesign --verify --strict`.
- **Проверено 2026-11-06:** macOS распознала приложение с локальной подписью и показала запрос на уведомления (журнал `usernoted`: «Sending request for permission»). Риск «уведомления недоступны без Apple ID» не подтвердился.
- **Особенность:** если запрос закрыть или отказать, macOS отвечает на него ошибкой «Notifications are not allowed». Это учтено: `NotificationPermission.afterRequestError` берёт решение, сохранённое системой, и покрыто тестами.
- **Альтернативы:** бесплатный Apple ID в Xcode (Personal Team). На Mac уже есть сертификат разработчика, но он выпущен на **другой** Apple ID — без разрешения владельца его не используем.

### 5. Минимальные права приложения
- «Песочница» (App Sandbox) и только исходящая сеть (`com.apple.security.network.client`), защищённая среда выполнения (hardened runtime).
- В финальной сборке отключено отладочное разрешение `get-task-allow` (`CODE_SIGN_INJECT_BASE_ENTITLEMENTS = NO` для Release). Проверено командой `codesign -d --entitlements`.
- **Почему:** стандарт, модуль Б — минимальные права, отладочные возможности в «проде» выключены.

### 6. Отладочная и финальная сборки — разные приложения
- Debug: `com.lavmoviesstudio.ipchek.dev`, имя «IPCHEK Dev». Release: `com.lavmoviesstudio.ipchek`, имя «IPCHEK».
- **Почему:** у разработки свои настройки и история, рабочие данные она не трогает (стандарт, модуль А — окружения разделены).
- Префикс `com.lavmoviesstudio` выбран по умолчанию: своего домена нет, приложение не публикуется.

### 7. Конфигурация без переменных окружения и `.env`
- **Почему:** секретов нет, сервера нет. Вместо проверки переменных окружения при старте — проверка настроек: `MonitorSettings.validated` (неверное значение → значение по умолчанию + запись в журнал). Покрыто тестами.
- Значения «вкл/выкл» и числа из UserDefaults различаются по типу CFBoolean, иначе 0 и 1 молча становились бы «выкл/вкл».

### 8. Строгость кода: Swift 6, предупреждения = ошибки, swift-format
- Режим языка Swift 6 (строгая проверка многопоточности), `SWIFT_TREAT_WARNINGS_AS_ERRORS`, в пакете — `.treatAllWarnings(as: .error)`.
- Оформление и линтер — `swift-format` 6.3.0 из состава Xcode, режим `--strict`. Проверено: на плохо оформленном файле линтер возвращает ошибку.
- **Альтернативы:** SwiftLint — ещё одна внешняя программа; пока не нужна.
- **Источник:** PackageDescription.swiftinterface (Xcode 26.6): `treatAllWarnings(as:)` и `.macOS(.v26)` доступны с tools-version 6.2.

### 9. Тесты — Swift Testing
- Встроен в Xcode, понятные названия тестов по-русски, таблицы примеров.

## 2026-11-06 — этап 2, «Есть ли интернет»

### 13. Проверка связи — HTTP-запросы со строгим ответом, а не «открылось ли соединение» (согласовано с владельцем)
- **Почему:** VPN-программа владельца (весь трафик идёт через её интерфейс `utun4`) сама отвечает на открытие любого TCP-соединения. Проверено: соединения с зарезервированными несуществующими адресами `192.0.2.1`, `198.51.100.7`, `203.0.113.9` «открывались» за 16–23 мс. HTTP-запросы к тем же адресам проваливаются, а к настоящим служебным адресам — проходят.
- **Адреса:** Россия — Яндекс `http://ipv4-internet.yandex.net/api/v0/ip` (код 200 и IP в тексте), запасной VK `HEAD http://vk.com/robots.txt` (код 200); зарубеж — Google `http://connectivitycheck.gstatic.com/generate_204`, запасной Cloudflare `http://cp.cloudflare.com/generate_204` (код 204).
- **Строгость:** переадресации не выполняются (по документации URLSession: `nil` в `willPerformHTTPRedirection` отдаёт сам ответ 3xx), поэтому страница входа в гостиничный Wi-Fi не сходит за интернет. Правило ответа — `ProbeExpectation`, покрыто тестами.
- **Цена:** зависимость от DNS (если DNS не работает, сайты не открываются — это честный разрыв); трафик около 15–20 МБ в сутки вместо 5–15.
- **Альтернатива:** проверка «напрямую мимо VPN» — показывает домашний интернет, но не видит проблем VPN; с частью VPN-программ обход не работает. Отложена до этапа 5 (сервер NL).

### 14. Простой HTTP разрешён точечно для четырёх проверочных адресов
- App Transport Security по умолчанию запрещает простой HTTP. Исключения — только для этих доменов (`App/Info.plist`), данных туда не отправляется, проверяется код ответа. Модуль Б («HTTPS везде») — осознанное исключение с причиной.

### 15. Быстрое подтверждение разрыва
- После неудачной проверки, пока разрыв или «частично» не решены, следующая проверка — через 1 с (а не через 5). Таймаут проверки — 2 с (живые серверы отвечают за 0,05–0,45 с). Итог: разрыв определяется примерно за 14 с, как обещано в паспорте.

### 16. Что считается потерями
- Потери — случайные сбои. Неудачи, из которых сложился разрыв или «частично», в потери не идут. Свежие неудачи подряд, которые ещё могут стать разрывом, не учитываются, пока не решено. Найдено тестами: иначе после разрыва панель минуту показывала бы «нестабильно», а перед «частично» мелькало бы «нестабильно».

### 17. Цветной значок в строке меню
- Строка меню перекрашивает обычные значки в один цвет, поэтому значок собирается как `NSImage` с `NSImage.SymbolConfiguration(paletteColors:)` и `isTemplate = false` (AppKit, macOS 12+). Форма своя для каждого состояния (`wifi`, `wifi.exclamationmark`, `wifi.slash`), чтобы различалось и без цвета.

### 18. Значок приложения рисуется скриптом
- `scripts/make-app-icon.swift` (команда `make icon`): свой рисунок волн, без SF Symbols (их лицензия запрещает использование в значках приложений). Фон сплошной на весь квадрат: по имеющимся сведениям, macOS 26 сама скругляет такие значки. **Не проверено на экране** — оценивает владелец.
